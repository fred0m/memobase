## 3. D3 重跑 T-D 回归（双指标：MRR@10 事件段 + Recall@全注入集）

**度量升级**（小三月 §1.3）：MRR@10 只算事件段（事件腿内部排序质量），概要段是注入文本不参与排名；Recall@全注入集 算概要段+事件段并集（信息到没到上下文）。

### 结果（36 条基准，同口径对照）

| 场景 | 混合链路 | 对照（同口径）| ΔMRR |
|---|---|---|---|
| all | **0.760** / 0.600 | 0.755 / 0.594 | **+0.005** ✅ |
| auto | 0.708 | 0.708 | 0 ✅ |
| active | 0.781 | 0.781 | 0 ✅ |
| temporal | 0.667 | 0.667 | 0 ✅ |
| entity | 1.000 | 1.000 | 0 ✅ |
| vague | 0.575 | 0.542 | **+0.033** ✅ |

**全部场景 ≥ 对照 -0.05，无回归。**

### 诚实声明
1. **对照基线从 0.769 降到 0.755**——不是概要层问题，是口径统一：之前对照用全列表（无预算截断），现在用预算截断后的事件段（900 字符）。v3 基线 0.769 是"全列表"口径，0.755 才是"真实注入"口径。
2. **概要段对 Recall 无显著增益**（0.600 vs 0.594）——350 预算只覆盖 5-6 行，精确行匹配可能没匹配到 gold 行。符合小三月 §1.3 判断：概要段是注入文本，MRR/Recall 测不出它的价值——价值在"LLM 读上下文时看到日概要形状"。
3. **绝对阈值 `all MRR ≥ 0.85` 不适用**——那是文档粒度（宽松）的预期，事件粒度 v3 基线才 0.769，0.85 是口径错配。
